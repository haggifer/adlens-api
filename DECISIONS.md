# AdLens backend — key decisions

Records the non-obvious architecture choices for the off-Firebase stack. Companion: the migration plan in the design-docs drive folder.

- **MongoDB Atlas + Mongoose** over Postgres/Prisma. The job document (nested `media` + `analysis`) is document-shaped, and MongoDB is the portfolio's demand gap. Atlas M0 (europe-west1) is the free tier; Change Streams (needed for realtime) require the replica set it provides.
- **NestJS on Cloud Run** (CommonJS). Guards/pipes/DI make ownership + quota explicit. One image, two entry points: the API service (`node dist/main`) and the on-demand analysis worker (`node dist/worker`), each with its own composition root.
- **Better Auth** (email/password, Mongo adapter, bearer plugin). Loads fine under Node 22 CommonJS. Mounted before the body parser; cross-origin uses a bearer token (no third-party cookies). Social login can be added later behind the same guard.
- **On-demand Cloud Run Job for analysis (2026-09-15), replacing BullMQ on Redis.** The first off-Firebase version used a BullMQ consumer in a separate Cloud Run service with one always-on instance. At about three analyses a week that instance was idle over 99% of the time for a standing monthly cost. The analysis is a finite task (download, one Vertex call, write result, exit), so it now runs as a Cloud Run Job (`adlens-analyze`, `node dist/worker`) executed by the API through the Cloud Run Admin API with env overrides, `--max-retries=2`, and an idempotent runner (returns early if the job is already `analyzed`). Idle cost is zero; Redis and BullMQ are removed. Cloud Run worker pools with the external-metrics autoscaler were the alternative that would have kept BullMQ while scaling to zero — rejected as more moving parts for no benefit at this load. Cloud Tasks pushing to a scale-to-zero service was the pre-migration design and remains a valid alternative.
- **Socket.IO + MongoDB Change Streams** for realtime job updates, replacing Firestore `onSnapshot`. One change-stream watcher per API instance; a shared adapter would be the scaling step once the API runs more than one instance with sticky sessions disabled.
- **GCS V4 signed uploads** to a EU bucket (`adlens-ca57f-uploads`, europe-west1), co-located with compute. The Cloud Run runtime SA signs via `iam.serviceAccounts.signBlob` (granted on itself); local signing needs a SA key, so signing is exercised on deploy.
- **Gemini on Vertex AI** via ADC (no key). `gemini-3.6-flash` on the multi-region `global` endpoint (3.x isn't on `us-central1`).
- **No Pulumi.** Infra is small and set-once, and IaC is already demonstrated twice in the portfolio (CDK, Terraform). Provisioning is a committed `infra/setup.sh` (`gcloud`) instead; Pulumi stays an optional later upgrade.
- **`adlens-shared`** is the schema-first contract (Zod source of truth, types inferred in place), dual-format (ESM + CJS with separate declarations) so the ESM web and CJS API both consume it; published to npm from CI with trusted publishing and pinned exactly, so the container and Vercel builds resolve it. A `file:` link only works locally, so it is never committed.

## Analysis rewrite (2026-09-23)

- **One owner for job status.** `JobLifecycle` performs every status change as a conditional `findOneAndUpdate` on the expected current status (`pending → verifying → queued → analyzing → analyzed | error`). Before, status was written ad hoc from two services, which allowed a double-submitted analyze to charge and dispatch twice, a late write to regress `analyzing` to `queued`, and jobs to stay in progress forever after a crashed worker.
- **Charge at queue time, refund at most once.** The atomic quota charge stays the gate (charging only after success would let concurrent requests race past a non-consuming check). The job stores the window it was charged to; the write that ends a run also clears it, and the pre-image of that write decides who refunds. Refunds only go back into the window they came from.
- **Attempt-aware retries.** Cloud Run retries any non-zero exit, so the worker reads `CLOUD_RUN_TASK_ATTEMPT` and decides: transient failures exit 1 while attempts remain; permanent failures (a rejected request, blocked content), or the last attempt, finalize the job and exit 0. Malformed or truncated model output counts as transient, because generation is stochastic (observed: one runaway reply in three identical calls); `maxOutputTokens` bounds what each attempt can cost.
- **Verification trusts the object, not the client.** Size and type come from the stored object's metadata; the signed upload URL binds the exact declared size. Only a definite problem with the file rejects (and deletes) it; storage or network trouble and an unfinished upload leave the job pending.
- **Lazy expiry instead of a scheduler.** Jobs abandoned mid-flight are expired when their owner reads their jobs. It needs no Cloud Scheduler and bounds the "stuck" window to the next time anyone looks.
- **The contract package holds only the contract.** The persistence-first schemas added in `adlens-shared` 0.3.0 were moved back into the API: the stored job is composed here from the shared building blocks plus server-only fields (owner, storage location, execution, accounting), so those never reach the client. `adlens-shared` 0.4.0 publishes the public job shape.
- **Gemini 3 runs at its default temperature.** Google recommends keeping Gemini 3 at 1.0 because lower values can make it loop; a 0.2 setting produced exactly that (an 18k-token, malformed reply) in testing.
- **Ports for the two external calls that matter.** `AnalysisDispatcher` (Cloud Run Job execution, or a local `node dist/worker` child process in development, the same entry point production runs) and `VideoReviewer` (Gemini on Vertex, with the response schema generated from the Zod schema that parses the reply).
- **Tests against a real MongoDB.** The lifecycle and quota guarantees live in query semantics, so their tests use `mongodb-memory-server` rather than mocked models.

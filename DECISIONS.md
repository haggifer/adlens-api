# AdLens backend — key decisions

Records the non-obvious architecture choices for the off-Firebase stack. Companion: the migration plan in the design-docs drive folder.

- **MongoDB Atlas + Mongoose** over Postgres/Prisma. The job document (nested `media` + `analysis`) is document-shaped, and MongoDB is the portfolio's demand gap. Atlas M0 (europe-west1) is the free tier; Change Streams (needed for realtime) require the replica set it provides.
- **NestJS on Cloud Run** (CommonJS). Guards/pipes/DI make ownership + quota explicit. One image, two entry points: the API service (`node dist/main`) and the on-demand analysis Cloud Run Job (`node dist/job`).
- **Better Auth** (email/password, Mongo adapter, bearer plugin). Loads fine under Node 22 CommonJS. Mounted before the body parser; cross-origin uses a bearer token (no third-party cookies). Social login can be added later behind the same guard.
- **On-demand Cloud Run Job for analysis (2026-09-15), replacing BullMQ on Redis.** The first off-Firebase version used a BullMQ consumer in a separate Cloud Run service with one always-on instance. At about three analyses a week that instance was idle over 99% of the time for a standing monthly cost. The analysis is a finite task (download, one Vertex call, write result, exit), so it now runs as a Cloud Run Job (`adlens-analyze`, `node dist/job`) executed by the API through the Cloud Run Admin API with env overrides, `--max-retries=2`, and an idempotent runner (returns early if the job is already `analyzed`). Idle cost is zero; Redis and BullMQ are removed. Cloud Run worker pools with the external-metrics autoscaler were the alternative that would have kept BullMQ while scaling to zero — rejected as more moving parts for no benefit at this load. Cloud Tasks pushing to a scale-to-zero service was the pre-migration design and remains a valid alternative.
- **Socket.IO + MongoDB Change Streams** for realtime job updates, replacing Firestore `onSnapshot`. One change-stream watcher per API instance; a shared adapter would be the scaling step once the API runs more than one instance with sticky sessions disabled.
- **GCS V4 signed uploads** to a EU bucket (`adlens-ca57f-uploads`, europe-west1), co-located with compute. The Cloud Run runtime SA signs via `iam.serviceAccounts.signBlob` (granted on itself); local signing needs a SA key, so signing is exercised on deploy.
- **Gemini on Vertex AI** via ADC (no key). `gemini-3.6-flash` on the multi-region `global` endpoint (3.x isn't on `us-central1`).
- **No Pulumi.** Infra is small and set-once, and IaC is already demonstrated twice in the portfolio (CDK, Terraform). Provisioning is a committed `infra/setup.sh` (`gcloud`) instead; Pulumi stays an optional later upgrade.
- **`adlens-shared`** is the schema-first contract (Zod source of truth → generated types), dual-format (ESM + CJS) so the ESM web and CJS API both consume it; published to npm and pinned exactly (`adlens-shared@0.2.0`) so the container and Vercel builds resolve it — a `file:` link only works locally.
